# Eternal Launcher — RoadMap & Next Agent Execution Plan

Документ для передачи следующему ИИ-агенту или разработчику. Содержит ключевой контекст архитектуры, стек, принятые решения и следующие задачи.

---

## 1. Специфика проекта и текущий статус
- **Тип лаунчера:** Лаунчер для оффлайн/пиратского Minecraft (аккаунты Ely.by с скинами + локальные оффлайн профили).
- **Стек:** Electron + React 18 + TypeScript + Tailwind CSS / Vanilla CSS + Framer Motion.
- **Готовые модули:**
  - Красивый кастомный UI без лишних моков и плейсхолдеров.
  - Управление сборками / инстансами (версии Vanilla, Fabric, Forge, NeoForge).
  - Модуль **«КОНТЕНТ»** (Modrinth + CurseForge) с переключением: **Моды** (`/mods`), **Текстуры** (`/resourcepacks`), **Шейдеры** (`/shaderpacks`). Мгновенная загрузка без задержек.
  - Локализация: **English (US)**, **Bri'ish English (Bo'o o' wa'a)**, **Русский**.
  - Полная поддержка Ely.by (2FA, авторизация через IPC без CORS, рендер скинов, смена скина, встроенное окно).

## 2. Ключевые архитектурные решения (Language & Stack)

### А. Связка Node.js + Rust: гибридный движок распаковки и валидации (Rust Engine)
* **Архитектура связки:**
  - **Node.js (Electron main):** управление UI, скачивание манифестов Mojang, HTTP/HTTPS стриминг файлов и библиотек, работа с сетью, авторизация Ely.by API.
  - **Rust High-Performance Engine (`src-tauri/src/engine`):**
    - `extractor.rs`: сверхбыстрая параллельная распаковка `.zip`/`.jar` архивов (`zip` + буферизованные потоки, защита от Zip Slip), распаковка нативных библиотек (`extract_natives`) с фильтрацией `META-INF` и сигнатур.
    - `verifier.rs`: многопоточная валидация тысяч игровых ассетов (`rayon` + `sha1`/`sha256`) параллельно на всех ядрах процессора (ускорение в 30–50 раз по сравнению с последовательным event loop в JS).
    - `hasher.rs`: параллельное хеширование папок с модами (`/mods/*.jar`) для мгновенной сверки версий с Modrinth/CurseForge.
  - **Интерфейсы доступа:**
    - Для **Tauri:** нативные команды `tauri::command` в `src-tauri/src/lib.rs`.
    - Для **Electron:** бинарный CLI `mc_engine` (`npm run rust:build`) с IPC вызовами `window.electronAPI.rustExtractArchive`, `window.electronAPI.rustVerifyAssets`, `window.electronAPI.rustHashFile`.
    - Предусмотрен бесшовный прозрачный fallback на оптимизированные потоки Node.js, если бинарник Rust ещё не скомпилирован на машине разработчика.

## 3. Список следующих планов (Backlog для следующего агента)

### Задача 1. Реализация Загрузчика файлов Minecraft (Engine Downloader)
1. Получение манифеста версий Mojang (`https://piston-meta.mojang.com/mc/game/version_manifest_v2.json`).
2. Скачивание `client.jar` выбранной версии.
3. Парсинг и параллельное скачивание библиотек (`libraries`), учет OS rules (Windows / Linux / macOS, x64 / arm64).
4. Скачивание игровых ассетов (звуки, текстуры, локализации) по `assetIndex` хэшам Mojang.
5. Инсталлятор загрузчиков (Fabric Meta / Forge Installer / NeoForge).

### Задача 2. Запуск процесса Minecraft (Game Launch Execution)
1. Детект или скачивание нужной Java JRE (Java 8 для старых версий, Java 17 для 1.18+, Java 21 для 1.20.5+).
2. Сборка classpath (`libraries/*.jar` + `client.jar`).
3. Формирование аргументов запуска JVM (`-Xmx`, `-Xms`, natives path, auth аргументы):
   - `--username <username>`
   - `--uuid <uuid>`
   - `--accessToken <token>` (для Ely.by передавать токен сессии)
   - `--versionType ELauncher`
   - Для Ely.by: передача authlib-injector аргумента `-javaagent:authlib-injector.jar=https://authlib-injector.ely.by`.
4. Запуск через `child_process.spawn` с перехватом `stdout`/`stderr` в консоль лаунчера в реальном времени.

### Задача 3. Встраивание кастомного скрытого мода лаунчера
- Подготовить кастомный jar-мод (улучшения Fullbright, HUD брони, QoL и т.д).
- В установщике / лаунчере сделать механизм авто-внедрения:
  - Копирование мода в скрытую папку инстанса или автоматическое монтирование в загрузчик.
  - Проверка целостности и авто-обновление мода перед стартом игры.

### Задача 4. Полноценное оффлайн-сохранение и персистентность контента (Permanent Offline Cache)
- **Концепция:** Когда пользователь скачивает мод, ресурспак, шейдер или датапак, лаунчер сохраняет его «насовсем» в постоянное локальное хранилище лаунчера.
- **Работа без интернета:** 
  - Даже при полном отсутствии интернета скачанный контент гарантированно сохраняется в физических директориях сборки (`/mods`, `/resourcepacks`, `/shaderpacks`, `/saves/<мир>/datapacks`).
  - Лаунчер сохраняет локальные метаданные (название, иконку, автора, описание) в локальный кэш (IndexedDB / JSON), чтобы оффлайн-вкладка «Установлено» отображала полные карточки с иконками без обращения к сети.
  - Возможность экспорта / резервного копирования модов и датапаков между инстансами без повторного скачивания из сети.

### Задача 5. Модуль установки и управления Модпаками (Modpacks Engine: CurseForge / Modrinth .mrpack)
- **Цель:** Полноценная поддержка установки комплексных модпаков для пиратских/Offline/Ely.by инстансов с гарантией стабильности, отсутствием сетевых коллизий и защитой от конфликтов модов.
- **Ключевые принципы и требования:**
  1. **Интеграция в интерфейс & Выбор целевого инстанса:**
     - Модпаки устанавливаются строго в уже существующий, выбранный пользователем инстанс (Instance).
     - При запуске установки модпака отображается селектор доступных инстансов.
  2. **Предупреждающий модал изоляции (Safety Warning Modal):**
     - Перед началом загрузки пользователю показывается предупреждение:
       - Модпак глубоко модифицирует инстанс, перезаписывая конфигурационные файлы (`config`), скрипты (`kubejs`/`crafttweaker`), шейдеры и моды.
       - **Правило жесткой изоляции:** частичное/выборочное отключение и удаление модов внутри модпака блокируется во избежание «хвостов», крашей рецептов и десинхронизации клиента.
       - Удаление модпака осуществляется строго через полное удаление всего инстанса целиком с диска.
     - Установка начинается только после явного подтверждения пользователем.
  3. **Блокировка сети и ресурсов — Полноэкранный оверлей (Fullscreen Loading Screen):**
     - При старте процесса активируется полноэкранный блокирующий оверлей, полностью перекрывающий лаунчер.
     - Запрещаются любые фоновые и параллельные загрузки других модов/ресурспаков/модпаков до 100% завершения процесса. Это исключает исчерпание лимитов CDN/API (Rate Limits 429) и перегрузку интернет-канала пользователя.
     - На оверлее отображается:
       - Плавный общий прогресс-бар (0–100%).
       - Счётчик скачиваемых файлов (`X / Y файлов`).
       - Детальный динамический лог в реальном времени с именем текущего загружаемого мода/библиотеки.
  4. **Пошаговый технический алгоритм реализации (Pipeline):**
     - **Шаг 1. Загрузка архива модпака:**
       - Скачивание пакета (`.mrpack` для Modrinth или `.zip` для CurseForge) во временную папку лаунчера через стриминг Node.js (`undici`/`https`) в основном процессе Electron.
     - **Шаг 2. Распаковка и парсинг манифеста:**
       - Распаковка архива через нативный Rust-движок (`mc_engine extract` / fallback Node.js).
       - Чтение и строгая валидация манифеста:
         - *Modrinth (`modrinth.index.json`):* парсинг массива `files`, получение хэшей (SHA-1, SHA-512), путей назначения и прямых URL для загрузки.
         - *CurseForge (`manifest.json`):* парсинг `files` с `projectID` и `fileID`, запрос прямых URL скачивания через CurseForge API.
     - **Шаг 3. Пул параллельной загрузки зависимостей:**
       - Очередь скачивания с управляемым пулом потоков (concurrency 3–5) для предотвращения блокировок CDN.
       - Стриминг каждого файла в целевую директорию инстанса (`/mods`, `/resourcepacks` и др.) с проверкой хэшей через криптографический модуль (Rust `sha1`/`sha256` или Node.js `crypto`).
       - Отправка прогресса через IPC (`mainWindow.webContents.send('modpack-progress', {...})`) для обновления оверлея.
     - **Шаг 4. Развертывание оверридов (`overrides/`):**
       - Рекурсивное копирование содержимого папки `overrides/` из модпака напрямую в корень инстанса (замена конфигов, скриптов, текстур сборок).
     - **Шаг 5. Финализация и разблокировка:**
       - Удаление временных файлов архива и распакованного манифеста.
       - Сохранение метаданных модпака в конфигурации инстанса (`isModpack: true`, имя, версия, автор).
       - Снятие полноэкранного блокирующего оверлея и уведомление пользователя об успешном завершении.
  5. **Механизм удаления сборки (Hard Instance Deletion):**
     - Для инстансов с флагом `isModpack: true` интерфейс исключает тумблеры одиночного удаления модов.
     - Действие «Удалить» для такого инстанса вызывает полное и безвозвратное удаление директории инстанса через Node.js: `fs.rmSync(instancePath, { recursive: true, force: true })`, гарантируя отсутствие мусорных файлов на диске.

### Задача 6. Интеллектуальный резолвер зависимостей и конфликтов Fabric (Dependency & Conflict Solver Engine)
- **Цель:** Предотвратить «ад зависимостей» и краши клиента Fabric при установке взаимосвязанных модов (например, Iris + Sodium, Indium, Continuity и др.).
- **Критические причины ошибок и правила защиты:**
  1. **Жесткие связки (Iris + Sodium):** Каждая версия Iris требует конкретную минорную ветку Sodium (например, 0.5.x или 0.6.x), а Sodium объявляет несовместимость с более старыми/новыми Iris в поле `breaks`.
  2. **Запрет «жадных» авто-фиксов Fabric:** Встроенные рекомендации Fabric Loader ("Fix", "Replace mod...") учитывают только одно локальное нарушенное ограничение. Автоматическое применение таких подсказок **строго запрещено**, так как они ломают другие моды в сборке.
  3. **Каскадное падение общих зависимостей:** Понижение версии общей библиотеки/мода (например, Sodium или Fabric API) ломает всех остальных её потребителей. Любое изменение версии требует полного пересчёта всего графа сборки.
  4. **Запрет угадывания версий:** Запрещено хардкодить или угадывать совместимость. Данные берутся строго из `fabric.mod.json` внутри `.jar` и через Modrinth API.
- **Обязательный регламент и алгоритм работы резолвера:**
  - **Шаг 1. Безопасный снепшот (Safety Backup):**
    - Перед любым изменением содержимого папки `/mods` лаунчер автоматически создаёт полную копию в `/mods_backup_<timestamp>`.
  - **Шаг 2. Парсинг метаданных и построение графа ограничений:**
    - Из каждого `.jar` файла на диске читается `fabric.mod.json` (с помощью Rust-модуля распаковки или Node.js).
    - Формируется граф ограничений: для каждого мода извлекаются секции `depends` (обязательные зависимости с диапазонами версий SemVer) и `breaks` (запрещённые версии/моды).
    - Системные ID (`fabricloader`, `minecraft`, `java`) фильтруются и сверяются с конфигурацией инстанса.
  - **Шаг 3. Изоляция версии Minecraft и лоадера:**
    - Строгая фиксация целевой версии игры (например, `1.20.1`) и загрузчика (`fabric`). Смешивание файлов разных версий Minecraft блокируется на корню.
  - **Шаг 4. Выборка версий-кандидатов (Modrinth API):**
    - Для модов, участвующих в конфликте, лаунчер запрашивает через Modrinth API до 8 последних совместимых релизов (строго под целевую версию Minecraft и Fabric), отсортированных от новых к старым.
  - **Шаг 5. Поиск бесконфликтного набора (Constraint Satisfaction Solver):**
    - Алгоритм перебора находит такое сочетание версий, при котором **одновременно выполняются все `depends` и не нарушается ни одно условие `breaks`**.
    - **Если решение найдено:** лаунчер атомарно обновляет/устанавливает весь набор совместимых файлов за одну операцию.
    - **Если решение не существует:** папка `/mods` остаётся **в нетронутом состоянии** (никакие файлы не заменяются). Пользователю выводится понятное диалоговое окно с детальным описанием тупика зависимостей и предложенными действиями:
      - Убрать или заменить мод `X`.
      - Сменить версию мода `Y`.

- **Реализованная функциональность (Auto-Dependency Downloader):**
  - При установке любого мода (например, Xaero's WorldMap) лаунчер через Modrinth API анализирует массив `dependencies` (фильтр `dependency_type: "required"`).
  - Сверяет список установленных модов инстанса. Если требуемая зависимость (например, `fabric-api`, `cloth-config` или зависимый мод) ещё отсутствует в папке `/mods`, лаунчер на лету находит совместимый релиз под текущую версию Minecraft и загрузчик и **автоматически скачивает её вместе с основным модом**.
  - В интерфейсе отображается статус загрузки зависимостей и уведомление со списком установленных библиотек.

## 4. Папка `graphify-out`
- Папка `graphify-out` — это артефакт статического графа базы знаний/кодовой структуры, сгенерированный утилитой `graphify`.
- **Нужно ли её обновлять?**
  - **Обязательно обновлять не требуется при обычных правках UI/логики.** 
  - Обновлять её имеет смысл только тогда, когда в проект добавляются совершенно новые большие модули (например, полноценный загрузчик игры или C++/Rust биндинги), чтобы новый агент мог быстро просканировать граф связей.
